casca(1)

NOME

casca - abre shells e agentes de código em outros hosts por ssh + tmux

SINOPSE

casca tui
casca connect [-agent nome | -attach sessão | -cmd comando] [-name sessão] [-dir pasta] host
casca ls host
casca kill host sessão
casca status
casca serve [-listen endereços]
casca init | url | version
casca-gui [--open host[:agente]]...

DESCRIÇÃO

casca conecta num host por ssh(1), cria ou reanexa uma sessão tmux(1) lá e entrega o terminal. O agente (claude, codex, devin ou qualquer comando) roda no host, dentro do tmux. O casca só transporta o terminal.

Fechar o casca, desligar a máquina local ou perder a rede não encerra a sessão remota. Quando o ssh cai, o casca tenta de novo após 1, 2, 4, 8 e 15 segundos, e continua a cada 15 segundos sem limite. Ao voltar, ele reanexa a sessão existente. Ele não cria uma sessão nova nem relança o agente numa reconexão. Erro de autenticação não é repetido.

Numa sessão nova, o casca abre o shell de login do usuário no tmux e digita o comando do agente nele. O agente herda o PATH e os arquivos rc do usuário, e sair do agente deixa um shell.

O casca foi escrito para um Dell Latitude D610 (Pentium M de 32 bits, 2 GB de RAM), onde os agentes não rodam. O binário é estático, sem dependências, com 6,3 MB em linux/386.

COMANDOS

tui
Menu no terminal: escolhe o host, depois um agente ou uma sessão viva. O detach do tmux (Ctrl-b d) volta ao menu.
connect host
Abre uma sessão em primeiro plano, com reconexão. -agent usa um agente da configuração; a sessão tmux se chama c-nome. -attach reanexa uma sessão que já existe. -cmd digita um comando qualquer numa sessão nova. Sem nenhum dos três, usa o primeiro agente da configuração.
ls host
Lista em JSON as sessões tmux vivas no host: nome, clientes anexados, hora da última saída e comando em primeiro plano.
kill host sessão
Encerra a sessão tmux no host. O que estiver rodando nela termina.
status
Testa a porta ssh de cada host e imprime, em JSON, up, down ou unknown.
serve
Interface web (xterm.js) com as mesmas sessões. Exige o token da configuração. casca url imprime os endereços já com o token.
init
Cria a configuração padrão, se não existir.

Em todos, host é o nome ou o índice do host na configuração.

JANELA

casca-gui é uma janela GTK3 + VTE que roda casca connect em cada aba.

┌────────────────────────────────────────────────────────────┐
│ casca                  servidor · claude            –  □  × │
├──────────────────┬─────────────────────────────────────────┤
│ Hosts        ↻ + │ ⠹ ✻ servidor · claude  ×              + │
│ ● notebook       ├─────────────────────────────────────────┤
│ ● servidor     2 │ › conserte o teste que falha            │
│   ⠹ ✻ claude  1m │ ● Bash(go test ./...)                   │
│   ○ ◆ devin   3h │   ⎿  ok   parser   0.412s               │
│ ● gpu            │                                         │
│ ▸ 2 sem resposta │ tmux ls  git status   servidor · claude │
└──────────────────┴─────────────────────────────────────────┘

A lateral lista os hosts e, sob cada um, as sessões tmux vivas nele, abertas nesta janela ou não. O ponto de cada sessão aberta gira enquanto há saída no terminal e fica verde quando a saída para sem a aba estar em foco.

Atalhos: Ctrl+Shift+K nova sessão; Alt+1..9 e Ctrl+PgUp/PgDn trocam de aba; Ctrl+Shift+W fecha a aba (a sessão continua no host); Ctrl+Shift+C/V copia e cola; Ctrl +/- muda a fonte; F11 tela cheia.

Requer python3-gi, gir1.2-gtk-3.0 e gir1.2-vte-2.91. No D610, a janela com uma sessão aberta usa cerca de 68 MB de RAM; cada sessão a mais, cerca de 7 MB e um processo ssh.

ARQUIVOS

~/.config/casca/config.json
Token, endereços de escuta, hosts, agentes e snippets. É recarregado ao ser salvo. -conf caminho usa outro arquivo.
{
  "listen":   "127.0.0.1:7681,tailscale:7681",
  "hosts":    [{"name": "servidor", "target": "dev@100.64.0.5", "dir": "~/proj"}],
  "agents":   [{"name": "claude", "cmd": "claude", "tmux": true}],
  "snippets": [{"label": "git status", "cmd": "git status\n"}]
}

AMBIENTE

CASCA_SSH
Programa usado no lugar de ssh.
CASCA_CONF, CASCA_BIN
Lidos só pelo casca-gui: arquivo de configuração e caminho do binário.

SEGURANÇA

O casca não guarda senhas nem chaves. Ele executa o ssh do sistema, com as chaves e o known_hosts que o usuário já tem. Não há conta, sincronização ou serviço externo.

casca serve escuta em 127.0.0.1 e, com tailscale:porta, no IP da tailnet. Nunca em 0.0.0.0. O acesso exige o token e a origem das requisições é conferida. O tráfego é HTTP sem TLS.

Hosts que seguram a conexão até uma pessoa aprovar (Tailscale SSH em modo check) mostram o link na aba. O casca espera até 10 minutos.

INSTALAÇÃO

curl -L -o casca https://github.com/jazzautomations/casca/releases/latest/download/casca-linux-386
chmod +x casca && ./casca init && ./casca tui

Há binários para linux-386, linux-amd64 e linux-arm64, com sha256sums.txt. Nos hosts de destino basta existir tmux.

Do código (Go 1.22 ou mais novo):

git clone https://github.com/jazzautomations/casca && cd casca && go build -o casca .
./deploy/install.sh root@HOST USUARIO     # instala noutra máquina, com a janela e um serviço runit
