NAME

casca - open shells and coding agents on other hosts over ssh + tmux

SYNOPSIS

casca tui
casca connect [-agent name | -attach session | -cmd command] [-name session] [-dir dir] host
casca ls host
casca kill host session
casca status
casca serve [-listen addresses]
casca init | url | version
casca-gui [--open host[:agent]]...

DESCRIPTION

casca connects to a host with ssh(1), creates or reattaches a tmux(1) session there and hands over the terminal. The agent (claude, codex, devin or any command) runs on the host, inside tmux. casca only carries the terminal.

Closing casca, powering off the local machine or losing the network does not end the remote session. When ssh dies, casca retries after 1, 2, 4, 8 and 15 seconds, then every 15 seconds without limit. Once back, it reattaches the existing session. It does not create a new session or relaunch the agent on reconnect. Authentication errors are not retried.

For a new session, casca starts the user's login shell in tmux and types the agent command into it. The agent inherits the user's PATH and rc files, and quitting the agent leaves a shell.

casca was written for a Dell Latitude D610 (32-bit Pentium M, 2 GB of RAM), where the agents do not run. The binary is static, has no dependencies and is 6.3 MB on linux/386.

COMMANDS

tui
Terminal menu: pick the host, then an agent or a live session. Detaching from tmux (Ctrl-b d) returns to the menu.
connect host
Opens a session in the foreground, with reconnection. -agent uses an agent from the configuration; the tmux session is named c-name. -attach reattaches an existing session. -cmd types an arbitrary command into a new session. With none of the three, the first configured agent is used.
ls host
Lists, as JSON, the tmux sessions alive on the host: name, attached clients, time of last output and foreground command.
kill host session
Ends the tmux session on the host. Whatever runs in it terminates.
status
Probes each host's ssh port and prints, as JSON, up, down or unknown.
serve
Web interface (xterm.js) over the same sessions. Requires the token from the configuration. casca url prints the addresses with the token included.
init
Creates the default configuration if there is none.

In all of them, host is the host's name or index in the configuration.

WINDOW

casca-gui is a GTK3 + VTE window that runs casca connect in each tab. Its interface is in Portuguese.

┌────────────────────────────────────────────────────────────┐
│ casca                  servidor · claude            –  □  × │
├──────────────────┬─────────────────────────────────────────┤
│ Hosts        ↻ + │ ⠹ ✻ servidor · claude  ×              + │
│ ● notebook       ├─────────────────────────────────────────┤
│ ● servidor     2 │ › conserte o teste que falha            │
│   ⠹ ✻ claude  1m │ ● Bash(go test ./...)                   │
│   ○ ◆ devin   3h │   ⎿  ok   parser   0.412s               │
│ ● gpu            │                                         │
│ ▸ 2 sem resposta │ tmux ls  git status   servidor · claude │
└──────────────────┴─────────────────────────────────────────┘

The sidebar lists the hosts and, under each, the tmux sessions alive on it, open in this window or not. The dot of an open session spins while the terminal produces output and turns green when output stops while the tab is not in focus.

Keys: Ctrl+Shift+K new session; Alt+1..9 and Ctrl+PgUp/PgDn switch tabs; Ctrl+Shift+W closes the tab (the session stays on the host); Ctrl+Shift+C/V copy and paste; Ctrl +/- change the font; F11 full screen.

Requires python3-gi, gir1.2-gtk-3.0 and gir1.2-vte-2.91. On the D610, the window with one session open uses about 68 MB of RAM; each extra session, about 7 MB and one ssh process.

FILES

~/.config/casca/config.json
Token, listen addresses, hosts, agents and snippets. Reloaded when saved. -conf path uses another file.
{
  "listen":   "127.0.0.1:7681,tailscale:7681",
  "hosts":    [{"name": "server", "target": "dev@100.64.0.5", "dir": "~/proj"}],
  "agents":   [{"name": "claude", "cmd": "claude", "tmux": true}],
  "snippets": [{"label": "git status", "cmd": "git status\n"}]
}

ENVIRONMENT

CASCA_SSH
Program used instead of ssh.
CASCA_CONF, CASCA_BIN
Read only by casca-gui: configuration file and path of the binary.

SECURITY

casca stores no passwords or keys. It runs the system ssh, with the keys and known_hosts the user already has. There is no account, sync or external service.

casca serve listens on 127.0.0.1 and, with tailscale:port, on the tailnet IP. Never on 0.0.0.0. Access requires the token and the origin of requests is checked. Traffic is HTTP without TLS.

Hosts that hold the connection until a person approves (Tailscale SSH in check mode) show the link in the tab. casca waits up to 10 minutes.

INSTALLATION

curl -L -o casca https://github.com/jazzautomations/casca/releases/latest/download/casca-linux-386
chmod +x casca && ./casca init && ./casca tui

Binaries exist for linux-386, linux-amd64 and linux-arm64, with sha256sums.txt. Target hosts only need tmux.

From source (Go 1.22 or newer):

git clone https://github.com/jazzautomations/casca && cd casca && go build -o casca .
./deploy/install.sh root@HOST USER        # installs on another machine, with the window and a runit service
